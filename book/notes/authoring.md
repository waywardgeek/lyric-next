# Codebook authoring agreements

## Improve the language while constructing it

Bill explicitly authorizes Cadence to identify and propose language changes that clearly simplify construction or testing of this codebook. Explain the concrete benefit, tradeoffs, and any changed semantics while Bill can steer. Once Bill approves, implement the change immediately within that agreed scope; do not ask again for routine implementation permission or defer it merely because an earlier chapter is already complete.

Update the language specification, the original construction chapter(s), exercises, and independent retained graders together. Teach the construction where the next book execution needs it, rather than leaving a patch diary or a feature found only in the current compiler. Preserve historical verification claims and successful frozen student results; new changes are not retroactively tested by those runs and do not authorize rerunning a passing student.

This permission is specific to work on this codebook. It does not authorize unapproved language redesign, deployment, or unrelated work.


## Carry reconstruction feedback into the next execution

See the [Chapters 1–8 integration audit](student-feedback-audit.md) for the
reviewed reports and the construction sections that carry their lessons.

Audit each student's report and linked teaching notes against the construction
chapters. Integrate useful reasons and counterexamples where the mechanism is
taught; keeping a report alone does not close the loop. Preserve assistance and
historical test limits. Prose updates do not authorize rerunning a passing student.

Prepare complete public input bundles, including linked grammar reviews and the
pinned offline tooling needed by the assigned chapter. Probe the actual workload,
not only tool version output. Keep host-specific runtime paths in the scoped
environment recipe rather than hardcoding one host into language teaching.
Never solve a sandbox setup failure by silently installing or widening grants.

Use narrow checked edits: inspect every match before broad text replacement,
and retain failed build logs rather than hiding a mechanical editing mistake.
Generated identifiers are private unless explicitly part of a public interface;
source-pattern graders must not require the reference's naming or unused helpers.
